相同的 Bayer 数据能输出不同的颜色、边缘和暗部细节，因为 ISP 在读取、重建、滤波和编码颜色的各步都有参数。本节先按处理目标建立关系，再追本地 ISP V35 把参数写入硬件与返回统计的路径。

## 从 RAW 到应用输出，先分图像与控制

~~~text
图像输入（Bayer） → 传感器采样校正 → 彩色重建 → 降噪、颜色与色调处理 → YUV 输出
                         │             │                      │
                         └─────────────┴── 统计与测量 ─────────┘
                                               ↓
                                         3A 与 IQ 参数
                                               ↓
                                      sensor / ISP 参数更新
~~~

这是按目标整理的概念图。真实 V35 中部分降噪在 Bayer 域处理，另一些在亮度和色度域。某些模块可旁路、统计有不同取样点，配置函数在源码里出现的顺序不能据此推断像素硬件顺序。核对模式、硬件版本和 IQ 后才讨论实际启用。

## 采样校正修掉哪些系统误差

- **BLC/BLS 黑电平校正**扣掉没有光时也存在的码偏置，以免把它误当成光。四个 Bayer 位置可能独立设置。扣错会造成暗处抬黑、暗部截断或有颜色的阴影。
- **DPCC 坏点修正**识别或接收坏点位置，用邻近同色样本估计合理值。强修正可能误伤星点、细线或纹理。
- **LSC 镜头阴影校正**通过空间增益补偿暗角或颜色阴影，通常按通道查表与插值。角落抬亮后也会放大角落噪声。

在当前 SDK 的 `isp_bls_config()` 内，RAW_GBRG 分支将某个 BLS 段的 R、Gr、Gb、B 偏移写到与 Bayer 相位相关的寄存器。摘出 R 和 Gr 两项。

~~~c
isp3_param_write(params_vdev, pval->r, ISP3X_BLS1_C_FIXED, id);
isp3_param_write(params_vdev, pval->gr, ISP3X_BLS1_D_FIXED, id);
~~~

切换 Bayer 相位时相同通道的偏移要送到不同位置。出现暗处偏色可先验证像素原点、黑位表按哪个 Bayer 对齐，再去调矩阵或白平衡。

## 从单色采样重建颜色，再考虑颜色和纹理

| 模块 | 处理目的 | 调过头或配错时怎样观察 |
| --- | --- | --- |
| 去马赛克 Debayer | 从相邻 Bayer 位置估计每像素缺失分量 | 斜线和细纹可能出现假色、锯齿或拉链 |
| 白平衡增益 | 在当前光源下让中性灰的通道响应接近目标 | 中性灰明显偏色，或高增益通道先饱和 |
| CCM 颜色矩阵 | 用通道间映射修正色彩响应、转换目标基色 | 色卡上某些色块偏，灰白可能还近似正常 |
| GOC / DRC 等 | 用曲线或压缩映射改变亮度分布及中间调 | 暗部被挤压、局部反差过强或高光层次异常 |
| Bayer/亮度/色度降噪 | 用时域或空域信息抑制不同种类的噪声 | 静态平坦区干净但细纹变糊，运动可能残影 |
| 锐化与增强 | 增强边缘与高频细节 | 强边出现白边黑边，噪声也可能被拉高 |
| YUV 转换与下采样 | 变换颜色表示并输出相应布局 | 颜色矩阵、量化范围和 UV 解释不一致时偏色 |

以 GBRG 中的第 (1,1) 个 G 为例，左右邻近是 R，上下邻近是 B。简化插值先取两侧平均，结果可用白平衡增益调整。矩阵则能让某一通道同时受其它色分量影响。白平衡调通道比例和矩阵做颜色映射各有职责，靶场要既有中性块又有彩色块。输出的 histogram 只能显示所统计分量的分布，Y 几乎不变时仍可能出现严重色偏。

## 参数与统计如何与帧对应

历史 `rkisp-isp-subdev` 同时有 Bayer 图像输入、图像输出、参数 sink 和统计 source。图像是一条流，参数队列和统计队列各有缓冲与生命周期。V35 的 `rkisp_params_cfg_v35()` 在锁下查看参数队列，以 `frame_id` 匹配想配置的帧；旧包可进入专门的处理路径，未来包会等待。不能把提交参数成功自动当成下一帧已生效。

~~~c
if (module_cfg_update & ISP35_MODULE_DEBAYER)
    isp_debayer_config(params_vdev, &new_params->others.debayer_cfg, id);
~~~

`module_cfg_update` 指定要更新配置的模块。另一组 `module_en_update` 与 `module_ens` 管理哪些模块要改变开关、改变到何状态。存一份 IQ 参数时同时存这几类信息，才能知道配置最终是否作用在启用路径上。若要调试画面，既看实际参数包字段也看选用的路径。

<Sdk id="isp35-other-config" />

统计路径记录当前图像的 frame_id、驱动维护的 params_id，并填入 VB2 的 sequence 与时间戳，然后标 DONE。params_id 是匹配参数与统计的线索。它仍需要与 sensor 控制生效时刻、输入帧标识以及级间延迟一起核对。

~~~c
cur_stat_buf->frame_id = cur_frame_id;
cur_stat_buf->params_id = params_vdev->cur_frame_id;
~~~

## 先用人工样本预测变化，再检查运行态

在 WSL 仓库根目录执行。脚本将几个处理拆成可手算的输入，不调用设备或厂商 IQ。可<a :href="exampleFile" download="isp-stage-demo.awk">下载 isp-stage-demo.awk</a>。

~~~bash
LC_ALL=C awk -f learning-site/examples/isp-stage-demo.awk
rg -n 'rkisp-input-params|rkisp-statistics|SGBRG10|YUYV8' output/camera-check/isp-before.log
~~~

| 控制变量 | 本轮人工样本结果 | 实板证据应怎么取 |
| --- | --- | --- |
| 黑位 / 角落增益 | 减 16 后中心 64、角落 48，1.33× 角落增益拉回 64 | 固定均匀光场、RAW 同色平面、中心与四角的统计 |
| 坏点替换 | 255 的点按同色邻居中位数变成 64 | 同坐标连拍，区分常亮坏点和瞬态噪点 |
| 去马赛克 / 白平衡 / 矩阵 | 插值得 RGB 90/64/42；白平衡后 64/64/64；示意 CCM 保灰但改变彩色块 | 同场景灰阶和色卡，用 RAW 与 NV12 区分前级偏置与输出解释 |
| 降噪 | 平坦区一维样本标准差 2.55→0.38 | 比较固定 ROI 多帧统计，并检查细线与运动纹理 |
| 锐化 | 50/150 的边缘相邻点变为 25/175，出现过冲 | 固定斜边、关闭其它变更，比对边缘剖面及噪点 |

示意色调把 0.25 映射为 0.50，说明同一输入能对应不同的亮度观感。实际 ISP 的定点深度、顺序和算法由芯片模块与参数决定。只保留最终 JPEG 会丢失输入 Bayer、有效画质参数、输出编码前的帧，以及当前帧的统计和配置关联。分别保留这些信息，偏色时才能判断问题更接近解码、AWB、CCM 还是输出矩阵。当前可核对的是历史拓扑和离线模型，板端逐阶段 A/B 还要在能安全管理现有 3A 服务时做。

## 本节复盘

1. **为什么看到 RAW 就不能直接显示成全彩图？** Bayer 每位置主要提供一个分量，需要校正与插值，随后才有完整的颜色向量可调整。
2. **Y 直方图几乎不变而画面偏色，优先查哪里？** 先核对 UV 顺序、输出元数据与读取方式。换受控灰卡和色卡再观察 AWB、CCM 或色度处理。
3. **为什么只看驱动的模块配置调用顺序无法画硬件顺序？** 配置函数更新寄存器与软件状态，真实像素路径还由硬件模块、旁通和工作模式决定。
