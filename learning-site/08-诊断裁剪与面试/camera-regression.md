## 从低代价的短试验逐层加量

| 级别 | 工作负载 | 首要验收 |
| --- | --- | --- |
| 烟雾 | 取第一帧和有限小窗 | 模式、设备节点、时间戳、位深和解码 |
| 启停循环 | 固定负载多轮 STREAMON/OFF 或启停进程 | 每轮都能开与停，缓冲释放，稳定后资源回到合理区间 |
| 并发 | 预览、主录、副本/异规格备录、拍照依次加入 | 各支实际帧率、时间戳、文件可解码，拍照与 Video 同时完成 |
| 异常和恢复 | 慢消费者、截断文件、可控取消 | 观察哪层最先报错及恢复方式，不覆盖失败证据 |
| 长稳 | 充分运行、多种温度和代表性数据 | 尾延迟、掉帧、CPU/内存趋势、容量及温度变化 |

在实板用同一个镜头、光源、输入模式及固定可复现场景。用 run ID 表示一轮，标明是否重新初始化设备、清理等待及温度。错误应有对照和最小触发条件，成功数字要标样本数和时间。停止服务、重启、刷机在既有授权边界下需单独确认。

## 发现异常时先按最早变化拆开

- **源头帧周期已变化**　找 sensor 模式、VBLANK、AE、CIF/ISP 计数和接收告警。
- **源稳定但归还变慢**　在 FrameScope 查具体支路持有、槽位峰值和缺失项，再把该支路单独接空 sink 对照。
- **只有写盘慢**　用可控目标空间和速度，区分 muxer 结束、write 返回、sync 后持久化与块请求尾时延。两个存储位置还应明确是否同一设备。
- **退出后仍有内存**　核对各轮稳定快照、对象寿命与 dma-buf 消费者，有增长才明确扩大采样。池稳定和泄漏是两类结论。

回归报告至少写版本、接口、测试矩阵、次数、每轮时长、结果与现场日志。用“发生过一次”或“此窗未见”表达观测。复现前先确定反例的检测灵敏度。例如只看平均 fps 的门槛不能捕获毫秒级偶发卡顿。

## 本节复盘

1. **一次短采集全通过证明什么？** 证明当次特定模式的有限数据链。长时、不同负载、启停或故障恢复需要另行验收。
2. **发现录像文件不完整，先查哪些边界？** 看 EOS、muxer 结束、文件增长、写回与解码记录，保留最先报错和输入。
3. **怎样检验备录引起的反压？** 同场景只改变备支路速度或去掉该消费者，对比槽位持有和其它流的尾延迟，再恢复原设置复现。
